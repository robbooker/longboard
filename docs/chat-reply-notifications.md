# Public room reply notifications

New replies notify the thread starter and earlier participants in the same conversation, including nested replies. The sender is excluded. The existing in-app bell shows the thread's original excerpt and new reply snippet, with the existing room/message hash link opening that reply's conversation. Bot-authored replies also notify participants. Message edits do not create new reply fanout or reset read state; deleting the reply/root removes its related alerts.

The account-owned “Reply alerts in this inbox” toggle controls future reply alerts and persists across browsers. Existing unread alerts remain. Explicit mentions remain their independent available alert type; when a reply and mention target the same person, the unique account/message row becomes one contextual reply notification. Delivery is the existing in-app inbox only. Public-room chat has no connected email/push delivery preferences; the unrelated RVOL integrations and private feature-channel sound/settings were not reused.

Insertion and inbox reads use the existing `chat_account_has_room` helper and bilateral sender/root-author block checks. Existing reply alerts stop appearing after access is revoked or a participant blocks the sender/root author. New mentions also check current access and sender blocks so they cannot bypass the reply insertion guard. Legacy mention/announcement read behavior otherwise remains unchanged. No authentication/membership policy changes were made; the independent ShortScout membership ticket owns those helpers.

The additive migration preserves existing alert rows, service-role-only access, read cursors and old clients. Reply alerts count toward existing room-alert badges and stay unread when only the room feed is acknowledged, since that feed hides thread replies; explicit alert and all-read actions still acknowledge them. The migration digest is pinned in the ticket release plan; its login HTTP probe is only a public smoke check, not authenticated acceptance verification.

Verification uses synthetic accounts only: `node scripts/tests/chat-reply-notifications-database.mjs` (24 assertions plus client-role denial) and targeted activity/preference Vitest suites (8 tests). Mobile testing uses Chromium emulation. No production operations or real messages were performed.
