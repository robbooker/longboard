# Admin access to public chat rooms

Request ab7eba57-1328-4df6-b63d-eec6331776b6 restores access to all five public rooms for a verified Longboard administrator: LB, SOCIAL, SS and both announcement rooms. This deliberately supersedes the earlier no-admin-exception SS policy. An admin needs neither a ShortScout identity nor a Boardroom cohort tag. Non-admin SS access still requires exact Mastermind; non-admin LB access still requires cohort 1 or 2. Unknown room names remain denied.

The Longboard session resolves its role from the current profiles row, not token/user metadata. A valid linked ShortScout chat cookie can use the linked profile's current admin role for public-room access only; its user role remains non-admin, so private Features/admin actions are not elevated. Existing paid-provider and session-validity checks still apply to that cookie: expired or missing provider verification requires signing in through Longboard. Revoked profile admin status removes the public-room exception on the next request. No access.admin consumers exist outside the public-room helpers. DMs retain participant/ownership checks and private Features retain their separate membership list.

The SQL helper uses the same five-room allowlist and live profile role. Message RLS permits these public reads for admins; reaction RLS follows message visibility. Existing announcement writer authorization remains intact. Ordinary ShortScout website login and memberships are untouched. No real member's membership was changed.
