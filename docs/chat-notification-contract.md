# Notification Formatting and Clear Chat Notifications contract

Approved by the coordinator on October 1, 2026. Formatting owns the reaction event schema, activity projection, manual notification actions, bell, and additive types. Clear owns the new exact-visible action/RPC and visibility observers. Each worker edits only its isolated branch. Release order is Reactions Review, Notification Formatting, then Clear Chat Notifications.

`public.chat_reaction_notifications` stores `id uuid` (primary key), independent `seq bigint` identity, recipient `account_id uuid`, `reactor_member_id uuid`, exactly one of `room_message_id uuid` / `dm_message_id uuid`, `emoji text` (`like`, `heart`, `laugh`, `rob`), `created_at timestamptz`, and nullable `read_at timestamptz`. Account, reactor, and message foreign keys cascade on deletion. Recipient + target + reactor + emoji is unique for each target kind. RLS is enabled and only the service role has table/function access. Bodies, attachment data, and copied names are never stored in events.

Fresh reaction activation creates a fresh event ID/sequence for the eligible message author, excluding self. Repeated active writes do not create or revive an alert. Removing a reaction removes its event; reactivation creates a new event. There is no backfill, push fanout, or scheduler. Reads join live target content and names, filter deleted content, blocks, room access, and DM participation/status. Existing mention and DM read cursors keep their meanings.

`ChatActivity` keeps existing `mentions`, `dms`, counts, and cursors. Optional additions are `reactions`, `reactionCount`, and `reactionThrough`. A reaction entry is `{id, seq, kind:'room'|'dm', room? | conversationId?, messageId, author, emoji, preview, createdAt}`. Its message ID is the exact reacted row, including a reply. `reactionThrough` is the maximum eligible unread reaction sequence across all rows, independently of list truncation and `mentionThrough`. DM entries gain optional `messageId`, `preview`, and `createdAt` for the latest incoming unread message.

Clear matches the authenticated recipient, exact authorized target scope/message IDs, and each independent observed notification cursor. It must not use room message `unread_seq` to acknowledge reaction events. New events beyond that snapshot remain unread. A request is bounded to 100 exact message IDs. Only canonical visible rows in a visible, focused document and an active/focused pane qualify; hidden panes, covered dialogs, and search do not. Ordinary room reading does not require composer focus. Existing scroll and message unread sequence behavior stay intact.

The complete activity HTTP payload, including all lists and scalar counts/cursors, is bounded to 32 KiB serialized UTF-8. SQL bounds initial lists to 50 mentions, 100 DM conversations, and 50 reactions, previews to 240 characters, context to 96, and names to 100. The response trims oldest listed rows as needed, preserving complete counts and snapshot cursors. No per-notification fetches are introduced.

The bell title is location – name – action. Main previews show up to five lines. Brief reply/reaction context comes last in italic text. Reaction alerts show the actual room/DM-specific icon and reaction type, with the reacted-message preview. Existing navigation and manual read semantics remain available.
