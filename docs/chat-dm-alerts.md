# DM audio alerts

Implements fdd54c5d-3e6f-4db6-8779-f3276c354034. The DM sidebar offers a global enable switch, default Chime or Pulse and a test button. Each available conversation offers Use default, Chime, Pulse or Mute, plus a test button. Preferences are muted by default and saved under a member-specific localStorage key. They persist across visits in that browser, not across devices. No sound file or external audio service is loaded; tones use Web Audio oscillators with a short volume envelope.

Enable and test sound once to activate browser audio. The same browser may require another gesture after a fresh visit. Unavailable/blocked audio and unavailable storage produce visible guidance; visual unread badges continue working. Existing chat polling pauses while hidden/offline. New arrivals can produce one coalesced sound when the open chat resumes; this is not background push and cannot sound when the browser is closed. Multiple arrivals in one refresh play at most one eligible conversation's tone. Separate open browser tabs can each alert; this change does not coordinate playback between tabs.

The first inbox snapshot is silent history. A participant-only `latestIncomingSeq` in the existing inbox RPC advances only for incoming, undeleted DMs. Self sends, edits, read marks and duplicate refreshes do not advance it. The tracker advances even while muted and retains its high-water mark after deletions. Blocked, unavailable, declined and system conversations never alert. Unblocking establishes a new baseline without replaying withheld messages. Incoming new requests after initial load may alert. Opening a conversation does not replay its history.

Privacy: the RPC continues deriving the member from the server-verified actor passed by the existing authenticated API. It only includes participant conversations and returns cursor zero for either block direction or decline. Browser roles cannot execute the RPC; no new public grants are added. Preferences remain in the current browser and contain only choices keyed by conversation ID, not message bodies or member names. Migration is backward-compatible metadata only; old clients ignore the extra property. There are no membership, DM content, attachment, or private Features authorization changes.

Validation: 466 full unit/API tests across 68 files; eight new tracker/preference tests include initial history, duplicates, self/edit/read changes, deletion, blocked/declined/system suppression, unblocking, new requests, delayed-arrival coalescing and malformed preferences. `scripts/tests/chat-dm-sound-database.mjs` passes 14 isolated PGlite assertions for participant isolation, both block directions, decline, edit/delete/self cursors and denied browser-role RPC access. `scripts/tests/chat-dm-sound-browser.mjs` exercises actual Web Audio scheduling under Chromium with synthetic Alice/Bob accounts: Chime/Pulse, incoming-only alerts, repeat refresh, per-conversation override/mute, global mute, reload persistence/history silence, member isolation, keyboard enable and unavailable-audio guidance. Screenshots `/tmp/dm-alerts-desktop.png` and `/tmp/dm-alerts-mobile.png`; mobile is Chromium emulation at390px, not physical Safari. Scheduled tone frequencies/playback calls were observed; physical speaker output was not recorded. TypeScript, targeted ESLint and production build results are included in the final handoff.
