## How the code sees it (`lib/cmpSystem.ts`, fixture `lib/__tests__/fixtures/sgrx-2026-10-16.json`)

**With the script's default thresholds, the morning trade is not detected.**

1. Strong move fires at 09:00.
2. The pullback never registers: the 09:08 low (0.684) is **8.6%** above the 200
   SMA (0.6296); the Class B window is 7%. Rob's TradingView chart shows the
   washout wick near 0.66 (about 5% above), which would qualify. Polygon's
   aggregates do not have that print, so this is a data-vendor difference.
3. Even with a 9% window, the 1% dip tolerance misses: the 09:18 red candle's low
   (0.797) is 3.7% above the 9 EMA (0.769). On Rob's chart the dip candle is a
   tiny red candle near 0.77 right on the 9 EMA, which Polygon prints as a green
   09:14 bar (0.760 → 0.773).

With `proxPct: 9` and `dipTolPct: 4` (reported, not adopted as defaults) the port
reproduces the trade: Class B pullback 09:08, reclaim 09:10, dip 09:18 (high
0.828), **buy 09:22 at 0.8281**, **T1 0.89** (HOD), target hit 09:24. Its stop is
0.7326 (bounce lows 0.740 less 1%); with `includeReclaimLow` it is 0.6999.
Rob's 0.71–0.72 sits between the two. Version 1 and version 2 of the script give the same
result on this day.

Lesson for detectors: the thresholds are defaults, and near-threshold setups
flip with the data vendor. When the chart says Class B and the code says
nothing, report which threshold missed and by how much.
